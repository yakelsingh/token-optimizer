How it works

Six techniques, each in its own Python module. Every request is billed against a baseline that uses none of them.

1

Prompt optimization

Regex rules remove politeness and filler, shorten wordy phrases and drop repeated sentences. A short system prompt replaces the long default.

optimizer/prompt_optimizer.py
2

Smart system design

A semantic cache compares a new question with stored ones using cosine similarity. A hit costs zero tokens and returns in milliseconds.

optimizer/cache.py
3

Output control

The model is told the exact word limit and a hard max_tokens is set. Output tokens cost 3–5× more than input tokens.

optimizer/output_control.py
4

Chunking & retrieval

Documents become overlapping sentence-aware chunks, ranked with BM25. Only the top-k chunks go into the prompt.

optimizer/rag.py
5

Model selection

A complexity score (0–100) sends easy tasks to the small model and hard ones to the large model. The reasons are shown on every result.

optimizer/router.py
6

Post-processing

Code strips filler, trims to the word limit, builds bullets and JSON. The model only writes plain text, which is cheaper.

optimizer/postprocess.py

How savings are calculated

Baseline = verbose system prompt + raw prompt + every document + the large model + an unlimited answer. Savings are attributed in order (prompt → retrieval → output → model), so the five numbers always add up to the total. Prices are in optimizer/config.py.
